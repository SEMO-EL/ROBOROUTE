# M7 — Educational mode

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A "Learn" page that shows how RoboRoute reaches its conclusions, generated from the actual
computation on the user's scenario: an A* step-through, what the DP considered, and how a Monte
Carlo estimate converges.

**Spec:** user spec §14 (explanations from the actual algorithmic state — never generated text);
design §3 (traces come from the same code path as results).

## Global Constraints
- Every number shown comes from an API response for the current scenario.
- Replaying a trace must reproduce the search result (exit criterion of M7).

## Review Focus
1. A trace truncated by its event limit → replay says so and does not claim to show the final path
   (Task 1 test).
2. Scenario with no missions → each tab explains what is missing instead of failing (Task 4 test).
3. Simulation with 1 trial → convergence data still finite (Task 2 test).

### Task 1: Trace replay (pure) — `features/learn/replay.ts`: state after k expansions (closed,
open, current, g/h/f of current and of the cells it pushed); following parents from the goal
reproduces the search path and its cost.
### Task 2: Backend — `/simulate` returns convergence points (running mean with 95 % interval at
log-spaced trial counts); `/optimize` returns a DP summary (subsets examined, feasible subsets, the
best feasible sets with their completion time and expected score).
### Task 3: A* step-through UI — playback controls, grid view, current-step panel with g, h, f.
### Task 4: Learn page — tabs for pathfinding, optimisation (DP table + recurrence on the chosen
plan) and simulation (random variables and their distributions, convergence chart).
