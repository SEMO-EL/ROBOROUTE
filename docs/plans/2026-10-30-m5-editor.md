# M5 — Arena editor, missions, robot and calibration UI

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Users build and edit their own scenario: arena objects, missions, scoring, constraints,
robot parameters (from their own stopwatch measurements), with undo/redo and live validation.

**Spec:** `docs/architecture/phase-0-design.md` §3, §5, §6.2; user requirement: calibration from
simple measurements because teams have no instrumented robot.

## Global Constraints
- Forms show cm, degrees, cm/s, deg/s; the scenario stores SI. Conversion only in `lib/format`.
- Every edit goes through pure functions in `features/*/editing.ts` (unit-tested) and the project
  store's history (`edit`, `preview` + `commit` for drags, `undo`, `redo`, 100 steps).
- A drag is one undo step. Deleting a mission also removes constraints, scoring rules and travel
  overrides that reference it.
- Validation is the backend's: `/scenarios/validate` returns schema/reference issues **and**
  constraint warnings/errors (cycles, impossible missions); shown live (debounced).
- New ids are unique across missions, obstacles and zones.

## Review Focus
1. Deleting a mission that constraints and rules refer to leaves a valid scenario (Task 1 test).
2. Undo after a drag restores the position before the drag in one step (Task 2 test).
3. Typing an invalid number (empty, negative size) never writes NaN into the scenario (Task 4 test).
4. Calibration with one measurement shows the constant-speed warning and can still be applied
   (Task 6 test).
5. A new blank scenario is valid and loads in every page (Task 7 test).
